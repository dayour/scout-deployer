Overview

Microsoft Scout is Microsoft's first "Autopilot" agent - a Frontier-tier desktop app that reads/writes files, runs shell, drives a Playwright browser, and queries M365 via Work IQ. Once Scout was unblocked on the {{SCOUT_TENANT_NAME}} tenant, we built a full software-engineering platform around it: an object model, a 16-route control-plane API on the DarbotLM gateway ({{SCOUT_GATEWAY_HOST}}), and six repositories that turn the running fleet into programmable, composable, observable infrastructure - what we call Architecture Intelligence.

The control plane

scout-api exposes the fleet as /scout/* routes (health, info, catalog, fleet, nodes, policy, policy/render, sessions, tasks, manifest, schema), backed by scloud-om (Pydantic object model: Node/Agent/Policy/Session/Task/Fleet/Resource/Catalog).

The stack shape

scout-swe (framework) runs on aether (runtime) and is composed by weave (orchestration). scout-sdk is the canonical client; scout-app exposes it over MCP; scout-cli drives it from a terminal.

Identity & auth - {{SCOUT_APP_NAME}} Entra app registration

The control plane is only half the picture. Before any node can sign in to {{SCOUT_TENANT_NAME}} and clear the Frontier gate, the desktop client (Scout / {{SCOUT_APP_NAME}}) authenticates through a single Entra app registration. This is the identity layer of the architecture - incorporated here from the canonical record in swe_clippyclaw_app_reg.html.

Why it is shaped this way

Public client, no secret - a desktop app can't keep a secret; MSAL uses interactive + device-code + silent-refresh flows, zero credentials shipped.

Deep-link redirect, not localhost - registers custom scheme ms-clawpilot://; Electron intercepts via second-instance (Win/Linux) or open-url (macOS). Satisfies SPACE/compliance (no localhost web reply URL).

Delegated only - all Graph scopes act as the signed-in user; never application permissions. Source of truth: electron/auth/msal-provider.ts + deep-link-loopback.ts + electron-builder.json5.

How it fits Architecture Intelligence: this app-reg is the front door. MSAL acquires delegated Graph tokens which power Scout's Work IQ (mail/calendar/files/Teams/people); the same signed-in account holds the M365 Copilot license that satisfies the Frontier policy gate. Provisioning a new node therefore needs both - the policy key and a sign-in through this registration. Keep reviewed installer scripts as separate source files and supply tenant values through parameters or environment variables.

Provenance - {{SCOUT_TENANT_NAME}} deployment

Use this section to document a Scout deployment to the {{SCOUT_TENANT_NAME}} tenant. Tenant {{SCOUT_TENANT_ID}}; work account {{SCOUT_LICENSED_USER}}.

  1. Authenticate Azure + Entra to {{SCOUT_LICENSED_USER}} (subscription {{AZURE_SUBSCRIPTION_NAME}} {{AZURE_SUBSCRIPTION_ID}}).
  2. Hit the Frontier gate - "Scout hasn't been set up for your organization." Two-layer gate: org policy + licensed account.
  3. Tenant policy - Intune ADMX {{SCOUT_POLICY_NAME}} (policyId {{SCOUT_POLICY_ID}}) confirmed Enabled tenant-wide.
  4. Per-machine key - over SSH on {{SCOUT_PRIMARY_NODE_HOST}} set HKLM\SOFTWARE\Policies\Scout\AllowScoutFrontierAccess = 1 (exactly what the ADMX writes).
  5. Relaunch + sign in - waitlist cleared; validated genuine Microsoft-signed binary v0.22.333.0, GitHub Copilot identity login={{GITHUB_ACCOUNT}}, staff=true.
  6. Linux policy parity - reverse-engineered loader RF(win32) ?? VF(darwin) ?? HF(linux) ?? loadFromFile(); Linux reads camelCase /etc/clawpilot/policy.json.
  7. Control plane - on {{SCOUT_GATEWAY_HOST}} built scloud-om + scout-api (16 routes) + scout-cli into the DarbotLM gateway/proxy/router (commit 84d67d3).
  8. Platform repos - created scout-swe, aether, weave, then scout-app, scout-cli, and the canonical scout-sdk.
